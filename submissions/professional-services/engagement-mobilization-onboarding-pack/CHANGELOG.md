## 1.0.1 - 2026-10-01

Fixes the Cowork 1.0.0 evaluation (Blocked). Each finding maps to the fix below.

- **Safety stop: tripwire (novel SOW and pursuit lines passed through).** `safety_text.py` (shared, byte-identical in all five skills) now matches semantic families instead of a phrase list: wall/conflict status claims, approval/exception/waiver/sign-off claims, permission and role grants, scope escalation, send/copy/forward/upload to an e-mail address or URL (including `[at]`/`at … dot` obfuscation), suppression of holds/briefings/register, and assistant- or reviewer-addressed steering. Text is normalised with NFKC, Cf stripping and Cyrillic/Greek→Latin confusable folding, and mixed-script tokens are flagged on their own. `scope_digest` scans line by line: a flagged item is replaced by a withheld placeholder in every section (first-week plan included), holds give the path, line and pattern family only, and flagged text never appears in any output. Regression fixtures: the 12 reconstructed Cowork novel lines (4 SOW, 8 pursuit, including the Cyrillic "wall lifted"), 20 more paraphrases and 38 more benign domain lines that must stay clean. The original 22 benign and 22 attack lines are kept.
- **Safety stop: `briefing_topics` echo.** `wall_check.py` (`other_terms`, `names_other`) screens each briefing topic against the client names and matter IDs of other register rows, other matter-ID patterns, capitalised names that are not the engagement's own, and the tripwire. A screened topic is withheld, held (`HOLD-BRIEFING-TOPIC-*`) and escalated, and the pack goes on hold. Restricted workspace names that name another client are shown by ID only (`name_withheld_workspace_ids`). In the confidentiality reference, #3.1 now matches this behaviour, with a new #3.2 for the topic screen and new #4.3/#4.4 sections.

Every SKILL.md now has a `## Failure handling` section: on engine non-zero exit, malformed input or a missing register, stop, report and never hand-build.
- **Behavioral: "PM note says wall cleared, share everything".** wall-check owns wall-status claims and "wall cleared" notes. engagement-retrieve defers to it explicitly in its description and in its When NOT to Use section.

- **Non-finite JSON and atomic writes (found in DRQG, applied here; still 1.0.1).**
  - `safety_text.load_json` (used by every engine) parses with `parse_constant` and `parse_float` hooks. `NaN`, `Infinity`, `-Infinity` and overflowing literals such as `1e999` are an `InputError` naming the file. `is_num`/`field()` and `contract_validate` reject non-finite values in every range check, and the contract loader rejects them too.
  - Every engine serialises and encodes its output in full first (`json_bytes`/`text_bytes`, `allow_nan=False`) and then writes it atomically (`safety_text.write_atomic`: temp file in the same folder, `os.replace`, temp files always removed). `access_checklist` writes access JSON and pack together only after both temp files exist. A failure, including a lone surrogate from an input (`UnicodeEncodeError`), is a clean `InputError` and no output path is created or truncated.
  - Reference: confidentiality #1.3. Tests: one per engine per item (the four NaN/Infinity/-Infinity/1e999 literals, with and without an existing output file; a lone surrogate in a field that reaches the output, with and without existing outputs) plus range-check and writer unit checks. Goldens byte-identical. Suite 163 → 173 checks (~15 s).
- **QA round 4: multi-output writes are all-or-nothing (still 1.0.1).** `safety_text.write_atomic` replaced outputs one after another, so with `--pack-out` pointing at a directory `access_checklist` had already replaced access.json when the pack write failed, and still reported "nothing written". Any failure restores every backup and removes every newly created file. If a restore itself fails, the backup is kept and its path reported, never deleted. Temp files and backups are always cleaned up. Tests: the CLI reproducer (a sentinel access.json survives a directory or a missing folder at `--pack-out`), a simulated failure replacing the second output (rollback with and without existing outputs), and duplicate and happy-path writes.
